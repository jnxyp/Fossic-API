# Mod 综合推荐分

`GET /mods`（含 `include_modding=true`）在每个 Mod 对象中增加有限、非负数值字段 `mod_recommendation_score`。原创、汉化、转载使用相同协议，其他字段及列表顺序不变。该字段仅属于 Mod，游戏接口不变。

## 公式和下载口径

```text
D = 本 Mod 所有版本已登记附件下载量之和，attachment_id 跨版本去重
age = max(0, 本轮快照时间 - mod_update_date) / 86400
score = log10(1 + D) + 5 * max(0, 1 - age / 15)
```

每个 Mod 只有一个分数，切换前端游戏版本筛选不改变它。旧版本积累的下载会帮助同一 Mod 在新版本中的排名；该分数不是当前版本下载量或质量评分。

只计当前登记的有效附件，不恢复已被替换、删除映射的历史下载量。忽略未知/无效计数，0 是有效计数；同一 aid 第一个有效计数只加一次，未知记录不屏蔽后续有效记录。DAO 仍校验附件属于该帖。直链开关不影响计分，不跨 Mod 合并计数。不修改原始 null、重复映射或附件元数据。

下载底分不封顶、不随时间衰减。新鲜度从 5 分在 15 天内线性降至 0：0 天 5 分、7.5 天 2.5 分、15 天及之后 0 分。使用原有 UTC+8 日期解析后的 `mod_update_date`，不是帖子编辑时间或附件上传时间；无效日期不给新鲜度加分，未来日期最多加 5 分。全部下载未知时，计算下载底分按 0 处理，但不将原附件 null 改写为已知零；无计数的老牌 Mod 因此可能处于劣势。

## 快照与兼容性

`SnapshotCache._fetch_mods()` 在已有批量读取完成后，使用同一个时间计算所有 Mod，再生成默认/完整列表及元数据响应，全部成功后原子发布。每个 Mod 每轮只计算一次，无新增 SQL、依赖、调度器、环境变量或缓存层。

评分跟随既有 `MOD_CACHE_TIME`（默认 300 秒）刷新，不逐请求计算。请求仍只读预编码字节。评分/编码/数据库读取失败保留整个旧 Mod 快照，游戏快照可独立成功刷新。

不返回 `calculated_at` 或嵌套评分对象；本轮统一评分时间复用 `/status` 中的 `cache.mods.last_updated`。它只在该轮 Mod 快照成功发布后更新，代表该轮数据/评分时间，不代表每次 HTTP 请求的时间。客户端已加载的数据不会因时间流逝自行更新，不新增前端衰减计时器。

模型的 0.0 默认值仅用于内部 DAO 构造兼容，快照发布前始终显式计算并覆盖；不要直接序列化未评分的 DAO 结果作为公共响应。服务输出保留计算精度，不为展示提前四舍五入。

## 前端消费契约

综合推荐成为首次进入及清空条件后的默认选项，但实际排列仍由前端负责。分类内依次比较：

1. Mod 全部支持版本中的最高版本，使用既有游戏版本比较规则倒序。
2. 语言 chinese / no_text / english / other（C/N/E/O）。
3. `mod_recommendation_score` 倒序；同分按经典更新时间顺序和稳定标识兜底。

前端直接读取分数，不复制公式、不再按筛选版本计算推荐分。综合推荐的行内扩展信息仍为更新日期，不显示分数；按钮 tooltip 展示公式说明。原默认顺序仅改名经典顺序，算法不变。独立的「下载次数」排序仍按当前显示版本统计，不随本字段改为全版本累计。

旧前端可忽略新增字段；新前端应兼容字段缺失/非法的旧 API 数据，不崩溃、不本地补算。建议 API 先于前端上线。API 回滚前需核验前端兼容，不能假设新增字段始终存在。

## 本地验证

在仓库根目录使用 UTF-8 执行 `.venv/Scripts/python.exe -X utf8 -m pytest -q`。单元测试覆盖跨版本去重、未知计数与日期边界；快照/集成测试覆盖统一评分时间、每轮一次评分、失败保留、零请求计算、SQL 数量不变、原始数据/顺序不变及联合模型 OpenAPI。测试使用内存 SQLite，不访问开发者或生产数据库。
